# Scope cases (Spacing and Facing)

Every scope rule of the core as a named, testable case: the input geometry, the expected scope set,
and the mode. The scope is decided on the **source** side (D7); nothing here depends on the solver.

- **Unit level.** `scope_cases_test` (`spatialblend/space/scope_cases_test.cc`). Each case id appears in
  its test name with `-` written `_` (`SP-INSIDE-02` is `ScopeCases.SP_INSIDE_02_*`). The test runs the
  real source pipeline up to the in-scope matches (structural scope, family gates, people) and asserts
  the exact set and the mode. `CatalogCoverage.EveryCaseHasATest` fails when a case below has no test or
  a test has no case.
- **Scenario level** (the scenario harness and its `scope_case_scenarios_test` are not part of the public
  repository; the Scenario column is kept for reference). A named scenario
  of the scenario harness (scene, track, receiver variant: the real source Space, hub and receiver Space
  with the bounded driver) asserts, per frame, the scope the source sent, the proposal's replay pose and
  cause bits, and the yaw source. The scenes (`regions_a`, `regions_b`, and the existing ones) belong to
  the matrix and to `guards.csv`. The Scenario column is `file::TestName` (a bare file name is the scenario suite's, which is
  not part of the public repository; other paths are relative to `spatialblend/`), or an existing test
  that is the case's scenario. A `-` means the unit level is the whole case (the case has no behaviour
  of its own on the receiver). `CatalogCoverage` fails when a named scenario does not exist.
- **Standard world** of the unit tests (30 x 30 m room): `R1` (2,2)-(8,8) region with objects `O1`
  (3,3)-(4,4), `O2` (6,6)-(7,7) and an interaction region `Aff1`; `R2` (10,2)-(14,8) empty region; `L1`
  (16,2)-(19,8) flagged transfer leaf carrying `OL` (17,4)-(18,5); free-standing obstacles `T1`
  (2,12)-(5,14) and `C1` (6,12)-(7,14); overlapping obstacles `A` (10,12)-(13,15) and `B` (12,12)-(15,15);
  nested regions `R3` (2,16)-(8,22) > `R3a` (3,17)-(6,21) > `R3aO` (4,18)-(5,19); `R4` (22,2)-(26,8) with
  only an interaction child.

**Modes.** A Spacing scope is in one of three modes, a function of the source root point and the tree
(`ScopeResolver::ResolveSpacing`):

| mode | when | referents |
|---|---|---|
| `OUTSIDE` | the root point is in no referent's footprint | the container's non-interaction children (the border referent if D4 gives one), every person of the tree (D9) |
| `INTERIOR` (a) | the root point is inside a referent that has interior entities and is not a transfer leaf | the objects inside it, its border relation, the people inside it; the entered referent is the container |
| `REPLAY` (b) | inside a transfer leaf; or inside a referent with no interior entities | the entered referent alone; the receiver replays at the mapped position (chart / transfer mapping) |

Inside means the polygon point test of the referent's footprint, as everywhere else. Sibling Spacing
referents of an entered referent drop out of the scope.

**Decisions.** The Source column, and the comments and test names of the scope code, cite these rules:

| Tag | Rule |
|---|---|
| D1 | Facing visibility is ONE ray from the eye to the look-at contact, judged on the source side only. |
| D2 | A look-at is in the body only when it COINCIDES with the body; the receiver's body radius is not a scope. |
| D3 | AffordancePose is in scope while the anchor is inside its referent's parent object's region (the footprint of the nearest ancestor with an area); there is no near field. |
| D4 | A container has a border referent unless it is the room, a transfer leaf, or has no non-interaction children. |
| D5 | A containment-transfer leaf is the actor's whole scope; what it carries is covered by its correspondence. |
| D6 | A tag is the AffordancePose binding (which affordance kind an anchor binds to); it never narrows Spacing or Facing. |
| D7 | The scope is decided on the source side and is authoritative: a referent the receiver cannot map or ground drops, and with none left the proposal is NONE (there is no HOLD). |
| D8 | Spacing reachability is a geodesic path in the source free space F from the anchor to the referent's contact, with no snap tolerance. |
| D9 | Every other person in the same containment tree, at any depth, is a Spacing referent. |
| MA-1 | An element with no shared id is never a referent of any family (it has no counterpart on any receiver); the D7 rule applied to unshared elements. |

## v1 evidence (v1 measured, not read)

`v1_inside_scope_test` runs v1 (a real `spatialblend::Space`, three affordance volumes) and v2 on the same 700 positions. Measured in v1: while the source is inside volume A the cached intent timeline still carries B and S with finite step counts (A has steps = 1, then inf after leaving); what drops the others is the receiver: `IsInsideTarget()` of A's approach makes `ApplySnapTransformIfInsideTarget` answer A alone. The test therefore compares the set the receiver answers (inside approach, else the valid timeline) with v2's scope. Inside: both give the entered referent alone. Before A: both give all three. After leaving A: v1 keeps only targets it is closing on (its time-based notion, not scope; v2's scope is geometric and keeps all three, the weights carry the timing).
